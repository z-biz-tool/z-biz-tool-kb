## 1.2 已确认缺陷（有直接源码证据）

### D-01 PDF 文本提取为字节过滤法，对真实 PDF 基本失效 【P0】

证据：[../../src-tauri/src/rag.rs](../../src-tauri/src/rag.rs) L105-L130 `extract_text_from_pdf`——扫描字节流，把 `(` 与 `)` 之间的字节逐字节 `b as char` 拼接。

- 现代 PDF 的内容流几乎总是 FlateDecode 压缩，此法提取不到任何正文；
- `b as char` 是 Latin-1 语义，多字节 UTF-8 中文会变成乱码字符；
- 代码注释自认："生产环境应使用 pdf-extract 等库"（L88）。

后果：PDF 上传"成功"、chunk_count > 0，但切片内容是不可读噪声 → 检索永远命中不了 → 用户视角"知识库坏了"。

### D-02 Word(.docx) 提取同样失效 【P0】

证据：[../../src-tauri/src/rag.rs](../../src-tauri/src/rag.rs) L92-L96 走 `extract_text_from_binary`（L133-L156，提取连续可打印字节段）。docx 是 ZIP 容器，正文在压缩的 `word/document.xml` 内，此法只能提到 ZIP 目录项里的文件名碎片。`.doc`（OLE2 二进制）同理。

### D-03 `delete_document` 存在路径穿越 【P0，安全】

证据：[../../src-tauri/src/commands.rs](../../src-tauri/src/commands.rs) L96-L100 直接把前端传入的 `doc_id` 交给 [../../src-tauri/src/rag.rs](../../src-tauri/src/rag.rs) L262-L274：

```rust
let meta_path = data_dir.join("documents").join(format!("{}.json", doc_id));
```

`doc_id` 无任何校验。传入 `../../foo` 类值可删除 app_data_dir 之外的任意 `.json` 文件（受 `.json` 后缀拼接限制，但同机其他应用/本工具未来数据都可能中招）。对比：`upload_document` 的 doc_id 生成反而做了字符清洗（commands.rs L45-L50），说明清洗意识存在但未覆盖删除路径。

### D-04 删除文档无二次确认、无回收站，单击即物理删除 【P0】

证据：[../../src/components/DocumentList.tsx](../../src/components/DocumentList.tsx) L89-L95 `handleDelete` 直接 `await deleteDocument(doc.id)`；L169-L180 删除按钮无 Popconfirm/Modal.confirm 包裹（全仓 grep `confirm|Popconfirm` 仅命中 UploadButton.tsx L135 的 `confirmLoading`，与删除无关）。后端 [../../src-tauri/src/rag.rs](../../src-tauri/src/rag.rs) L262-L274 为 `fs::remove_file` 物理删除，无任何恢复手段。

### D-05 每次问答全量加载所有切片，无索引结构 【P1，性能】

证据：[../../src-tauri/src/commands.rs](../../src-tauri/src/commands.rs) L127-L128 每次 `ask_question` 调用 `load_all_chunks`；[../../src-tauri/src/rag.rs](../../src-tauri/src/rag.rs) L277-L299 遍历 `chunks/` 目录逐文件 `read_to_string` + `serde_json::from_str`，全部装入 `Vec<Chunk>`；随后 L337-L351 对每个切片做全量子串 `matches()` 计数。复杂度 O(全部切片字节数 × 查询词数)，随库线性劣化，且每次提问都重复付出全量 IO+解析成本。

### D-06 检索仅 2-gram 词频计数，无 IDF/BM25，无同义词与语义能力 【P1，质量】

证据：[../../src-tauri/src/rag.rs](../../src-tauri/src/rag.rs) L307-L358 `keyword_search`：

- 查询侧生成中文 2-gram + 英文单词（L313-L330）；
- 打分 = 各 term 出现次数简单累加（L342-L345），常见词（如"文档"）与区分词（如"FlateDecode"）权重相同；
- 无 IDF、无字段加权（标题/正文同权）、无同义词扩展、无拼写容错；
- L347 归一化 `chunk.text.len()` 用的是**字节长度**，中文每字 3 字节，中英混排文档间归一化不公平。

需要明确：**当前没有任何向量/语义/embedding 检索实现**（全仓 grep 无 embedding/vector/similarity 相关代码），README 也只声明"关键词检索"（[../../README.md](../../README.md) L9），文档与实现一致，不存在虚假宣传，但能力上限低。

### D-07 API Key 明文落盘 【P0，安全】

证据：[../../src-tauri/src/rag.rs](../../src-tauri/src/rag.rs) L478-L484 `save_llm_config` 将含 `api_key` 的结构 `serde_json::to_string_pretty` 后直接 `fs::write` 到 `app_data_dir/llm_config.json`，无加密、无文件权限收紧、无 OS keychain。前端读取时 key 也完整回传到 webview（[../../src/stores/knowledgeStore.ts](../../src/stores/knowledgeStore.ts) L156-L163），并作为表单初值显示（[../../src/components/UploadButton.tsx](../../src/components/UploadButton.tsx) L142-L146，虽用 `Input.Password` 遮蔽，值仍在 DOM/内存中）。

### D-08 对话历史与检索历史完全不持久化 【P1】

证据：[../../src/stores/knowledgeStore.ts](../../src/stores/knowledgeStore.ts) L49 `messages: []` 仅内存态；zustand `create` 未用 `persist` 中间件（L70）；后端也无任何保存会话的 command（commands.rs 全部 6 个命令与会话无关）。重启应用即丢失全部问答记录——对知识工具而言，问答历史本身就是知识资产。

### D-09 问答无多轮上下文 【P1】

证据：[../../src-tauri/src/rag.rs](../../src-tauri/src/rag.rs) L408-L419 `call_llm` 的 messages 只有 system（含检索上下文）+ 当前 question 两条；[../../src-tauri/src/commands.rs](../../src-tauri/src/commands.rs) L121-L124 `ask_question` 签名只接收 `question`。用户追问"它的第二点展开讲讲"时，LLM 看不到前文，多轮对话实际不可用（UI 却呈现为连续对话，存在体验欺骗）。

### D-10 上传：无去重、无大小限制、原文不留存、进度条为假 【P1】

- 无去重：doc_id = 清洗后文件名 + 秒级时间戳（[../../src-tauri/src/commands.rs](../../src-tauri/src/commands.rs) L45-L50），同一文件重复上传产生多份切片（同秒上传则 doc_id 相同、静默互相覆盖），无内容哈希校验；
- 无大小限制：L33-L41 直接 `fs::metadata` + `read_file_content` 全量读入内存，超大文件可致内存峰值失控；
- **原文不留存**：upload 只从源路径读取内容后保存 meta+chunks（L26-L63），原始文件未复制进数据目录——用户移动/删除原文件后，引用无法回看原文，"来源可追溯"断链；
- 假进度条：[../../src/components/UploadButton.tsx](../../src/components/UploadButton.tsx) L33-L36 注释自认"模拟进度（invoke 为单次调用，无真实进度事件）"，后端无任何 `emit` 事件（全仓 grep 无命中）；
- 仅单文件：L17-L25 `open({ multiple: false })`，不支持多选/拖拽/文件夹导入。

### D-11 知识组织能力为零：无分类、标签、链接、笔记 【P1，产品】

证据：数据模型 `DocumentMeta`（[../../src-tauri/src/rag.rs](../../src-tauri/src/rag.rs) L15-L24）仅有 id/name/size/doc_type/chunk_count/created_at/status 七个字段；前端文档列表仅有按文件名的内存过滤（[../../src/components/DocumentList.tsx](../../src/components/DocumentList.tsx) L81-L86）。**不存在面向用户的全文搜索入口**——`keyword_search` 只服务于问答，用户无法直接"搜知识库看原文"。也没有手动录入知识条目的入口（只能上传文件）。

### D-12 `src/agent/` 是未接线的 SQL Agent 桩代码（死代码） 【P2，工程卫生】

证据：[../../src/agent/AgentManager.ts](../../src/agent/AgentManager.ts) L40、L77、L114、L151 四处 `// TODO: 调用 Agent 服务`，返回硬编码假响应（如 L44 拼接 `SELECT * FROM users ...`）；[../../src/agent/types.ts](../../src/agent/types.ts) L19-L27 `AgentContext` 是 connectionId/databaseType 等**数据库**概念；App.tsx 及任何组件均未 import `AgentPanel`/`useAgentStore`（grep 证实仅 agent 目录内部互相引用）。git log 显示其来自 "feat: add unified Agent component" 的跨项目统一模板。**审计结论：本项目当前不存在任何已实现的 Agent 能力**，该目录与知识库场景不匹配，属复制来的脚手架。

### D-13 LLM 调用非流式，打字机效果为前端模拟 【P2】

证据：[../../src-tauri/src/rag.rs](../../src-tauri/src/rag.rs) L429-L447 一次性 `send().await` + `resp.json()`，请求体无 `stream` 字段（L365-L371）；前端在完整答案返回后用 `setInterval` 每 20ms 吐 2 字模拟打字（[../../src/components/ChatPanel.tsx](../../src/components/ChatPanel.tsx) L227-L259）。长回答时用户面对"正在思考..."干等（60s 超时上限，rag.rs L424-L427）。

### D-14 Tauri 权限面偏宽 + CSP 关闭 【P1，安全】

证据：[../../src-tauri/capabilities/default.json](../../src-tauri/capabilities/default.json) L6-L12 授予 `core:default`、`clipboard-manager:default`、`dialog:default`、`fs:default`、`shell:default` 五项；而前端源码实际只用到 `plugin-dialog` 的 `open`（UploadButton.tsx L4、L17）。`tauri-plugin-fs` / `tauri-plugin-shell` 已注册（[../../src-tauri/src/lib.rs](../../src-tauri/src/lib.rs) L11-L12）却无对应前端调用——属多余攻击面。[../../src-tauri/tauri.conf.json](../../src-tauri/tauri.conf.json) L22-L24 `"csp": null` 显式关闭内容安全策略。

### D-15 元数据读取零容错，单文件损坏拖垮全局 【P0】

证据：[../../src-tauri/src/rag.rs](../../src-tauri/src/rag.rs) L244-L254 `list_documents` 与 L286-L296 `load_all_chunks` 中，任一 JSON 文件 `read_to_string`/`from_str` 失败即 `?`/`map_err` 整体返回 Err——一个损坏文件导致文档列表打不开、问答不可用。且 `fs::write` 非原子（L212、L229），写入中途崩溃/断电即产生半截 JSON，恰好触发本缺陷。

### D-16 并发写无任何保护 【P2】

证据：全部存储操作是直接 `fs::write`/`fs::remove_file`（rag.rs L212/L229/L267/L270），无文件锁、无临时文件+rename 原子替换、无版本号。`upload_document` 是同步 command，两个上传并发时若 doc_id 相同（同名同秒）会互相覆盖切片文件；写入与 `load_all_chunks` 并发时可能读到半截文件。

### D-17 切片参数硬编码且 `split_text` 有潜在死循环 【P2】

证据：chunk_size=500/overlap=100 硬编码于 [../../src-tauri/src/commands.rs](../../src-tauri/src/commands.rs) L42；[../../src-tauri/src/rag.rs](../../src-tauri/src/rag.rs) L165-L193 `split_text` 的防死循环保护（L186-L189）只覆盖 `start==0 && end==chunk_size` 一种情形——若未来把参数做成可配置且 overlap ≥ chunk_size，`start = end.saturating_sub(overlap)` 会倒退或原地踏步导致死循环。切片纯按字符数切割，不感知段落/标题边界，切片常把句子拦腰截断（影响检索与引用可读性）。

### D-18 相关度分数展示口径失真 【P2】

证据：前端把原始词频分直接当百分比显示：`相关度 {(citation.score * 100).toFixed(1)}%`（[../../src/components/ChatPanel.tsx](../../src/components/ChatPanel.tsx) L114-L116）。而后端 score 是"命中次数 / 长度因子"（rag.rs L342-L348），无上界、非概率，完全可能出现"相关度 340.0%"。违背"检索结果可解释"原则——展示了一个不可解释的数字。
