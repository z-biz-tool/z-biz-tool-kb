## 6.1 测试基础设施与夹具原则

- **Rust**：`cargo test`（单元 + 集成，tests/ 目录，规划新增）；LLM/网络一律 mock（本地 wiremock 或 trait 注入假 client），测试不产生真实 API 费用；
- **前端**：vitest + @testing-library/react（规划新增 devDependencies）；`invoke` 以 mock 模块替换，组件测试不依赖 Tauri 运行时；
- **端到端**：优先 Tauri 官方 webdriver（tauri-driver + WebdriverIO）；macOS 上 tauri-driver 支持受限，降级方案 = `npm run dev` 浏览器模式 + IPC mock 层跑关键流程，真机手工用例清单兜底；
- **夹具隔离（硬约束）**：所有涉及存储的用例必须在 `tempdir`（如 `assert_fs`/`tempfile` 创建的临时目录）中构造数据目录，用例结束自动销毁；**禁止读写真实 app_data_dir**，禁止依赖开发者本机残留数据；评测语料用 `eval/corpus/`（公开文档 + 自建样本）固定版本化；
- **CI 门禁**：单元测试 + 检索评测（05 文档 T3-09）进 PR 门禁；性能与故障注入夜间跑（耗时原因）；E2E 每 release tag 跑。

## 6.3 验收流程约定

1. 每项指标的报告（命令输出/截图/评测 JSON）存入 `doc/优化方案/验收记录/`（规划新增，届时创建）；
2. "通过"仅当用例在 CI 或本机按本文口径实际执行且留档；**未执行 = 未通过**，不允许以"代码已写"代替；
3. 回归门禁：任何 PR 使 RET-01 相对基线下降 > 3pp、或 SEC 任一项失败，即阻断合并；
4. 每阶段出口按 [05 文档 §5.7](./05_实施路线与任务拆解.md) 里程碑表勾验。
