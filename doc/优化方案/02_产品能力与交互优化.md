## 2.2 采集/录入

**现状**：唯一入口是文件选择对话框（[../../src/components/UploadButton.tsx](../../src/components/UploadButton.tsx) L14-L63），支持 pdf/doc/docx/txt/md 五种扩展名（L19-L24），单文件、假进度（D-10）。**不能手动录入知识**——想记一条"某个报错的解法"必须先存成 txt 文件再上传，与知识工具直觉相悖。

**缺口与目标设计**（按优先级）：

1. 【P0】**快速笔记录入**：新增"记一条"入口，标题 + Markdown 正文 + 标签，直接入库为一等知识条目（数据模型见 [03 文档 §3.5](./03_技术架构与性能优化.md) 的 `knowledge_items`）。手动条目与文档切片同库同检索。
2. 【P0】**剪贴板导入**：`clipboard-manager` 插件已安装且已授权（[../../src-tauri/capabilities/default.json](../../src-tauri/capabilities/default.json) L8）但前端从未调用——现成能力零成本启用"从剪贴板收藏选中文本"，自动记录来源应用/时间。
3. 【P1】**拖拽上传 + 多选**：dialog `open({ multiple: true })` + webview 拖拽事件；导入队列面板显示每个文件的真实状态（等待/提取中/切片中/完成/失败原因），依赖后端事件通道（见 2.7）。
4. 【P1】**原文留存**：上传时把源文件复制到数据目录 `originals/`，引用卡片可"查看原文"（对应 D-10 溯源断链）。超大文件（> 阈值，建议 50MB，可配置）仅存提取文本并明确告知用户。
5. 【P2】**网页剪藏**：仅做"粘贴 URL → 用户手动粘贴正文"的轻量形态；不引入 headless 抓取（超出桌面工具边界，且引入内容安全面，见 [04 文档 §4.5](./04_数据安全与可靠性.md)）。

## 2.3 结构化组织

**现状**：`DocumentMeta` 七字段（[../../src-tauri/src/rag.rs](../../src-tauri/src/rag.rs) L15-L24），侧栏是按时间倒序的平铺列表（L256-L258）。无文件夹、无标签、无排序切换、无重命名。

**目标设计**：

1. 【P1】**标签体系**：条目/文档多标签，侧栏增加标签过滤器；标签支持颜色。这是个人知识库最低成本的 organize 手段（Obsidian 理念），先于文件夹做。
2. 【P1】**收藏/文件夹（可选单层分组）**：不做多级页面树（Notion/语雀式树维护成本高，个人工具容易烂尾），只做单层"集合"（collection），一个条目可属多个集合。
3. 【P2】**智能分组建议**：基于已有标签与内容相似度提示"这两条知识可能属于同一主题"，用户确认后生效（Agent 建议不自动写库，原则见 [04 文档 §4.6](./04_数据安全与可靠性.md)）。
4. 【P1】**重命名与元信息编辑**：文档名当前即文件名，不可改；增加标题/备注/标签编辑面板。

## 2.4 全文与语义检索

**现状**：面向用户的搜索只有文档名子串过滤（[../../src/components/DocumentList.tsx](../../src/components/DocumentList.tsx) L81-L86，纯前端内存 filter）；`keyword_search` 只在问答链路内部使用，**用户无法直接搜内容看原文**。

**目标设计**：

1. 【P0】**全局搜索框（⌘K）**：直达切片/条目全文，结果按相关度排序，显示命中词高亮与上下文摘要，点击跳转条目详情。检索管线升级（BM25/分词/是否引入向量）在 [03 文档 §3.2](./03_技术架构与性能优化.md) 展开。
2. 【P0】**搜索结果可解释**：每条结果标注"为什么命中"（命中词列表 + 各自贡献分），替换当前失真的"相关度 xx%"（D-18）。分数展示契约：归一化到 0-1 的相对分，或展示 `BM25=12.3 · 命中: 关键词A×3, 关键词B×1`。
3. 【P1】**过滤器**：按类型（文档/笔记）、标签、时间范围过滤搜索结果。
4. 【P1】**问答内检索透明化**：ChatPanel 引用区已有（C-01），增加"本次检索共扫描 N 切片、命中 M 条、取 Top 5"的检索说明行，让用户理解答案的召回边界。
5. 【P2】**语义检索**：向量召回作为混合检索的一路（见 03 文档权衡），面向"换了说法就搜不到"的场景；上线前后必须用同一评测集对比（06 文档 §6.5）。

## 2.5 关联与引用、来源追溯

**现状**：`Citation` 已能定位 doc_id + chunk_index + 完整切片文本（C-01），但：切片无页码/段落号（PDF 提取法根本拿不到版面信息，D-01）；条目之间零关联；引用不能反查"这条知识被哪些问答引用过"。

**目标设计**：

1. 【P1】**条目间双向链接**：Markdown 正文内 `[[条目标题]]` 语法，保存时解析为链接表，条目详情页显示"链出/链入"。这是知识图谱（2.8）的数据基础。
2. 【P1】**引用定位增强**：`Chunk` 增加 `locator` 字段（PDF 页码 / Markdown 标题路径 / 纯文本行号区间），提取管线在解析阶段顺带产出（依赖 D-01 修复后使用真实解析库）。引用卡片显示"第 12 页 · §3.2"并支持打开原文定位。
3. 【P2】**问答→知识沉淀**：一条好的 AI 回答可一键"存为知识条目"，自动携带原始问题、引用列表作为 provenance；**存为草稿，用户编辑确认后入库**（Agent 不自动写库）。
4. 【P2】**反链面板**：条目详情显示引用过它的历史问答（依赖 2.9 会话持久化）。

**来源可信标注**：条目增加 `source_type`（用户上传 / 手动录入 / 剪贴板 / AI 生成草稿）与 `source_uri`（原文件路径或 URL），AI 生成的内容在未确认前始终带"AI 建议"角标——对应核心原则"知识来源可追溯"。

## 2.6 批量导入

**现状**：无（D-10，`multiple: false`）。

**目标设计**【P1】：

- 多文件选择 + 文件夹导入（遍历目录，按扩展名白名单过滤，跳过隐藏文件）；
- 导入前预检清单：文件名、大小、类型、预估切片数、**重复检测结果**（内容 SHA-256 与库内比对，见 [04 文档 §4.1](./04_数据安全与可靠性.md)），用户可勾选排除；
- 后台队列执行（Rust 侧独立 task），逐项 emit 进度事件，UI 显示 成功/失败/跳过 三态汇总；失败项可单独重试，失败原因可读（"PDF 加密无法解析"而非"上传失败: Err"）；
- 导入中关闭应用需有恢复策略：单文件粒度事务，中断后已完成部分保留，未完成部分标记 `failed` 可重试。

## 2.8 知识图谱

**现状**：无。

**目标设计**【P2，依赖 2.5 双向链接数据】：

- 数据即链接表（`links(from_item, to_item, kind)`），不做独立图数据库；
- 视图：以某条目为中心的局部图（1-2 跳邻居）优先于全局大图（个人库全局图信息密度低、渲染成本高）；
- 节点 = 条目/文档，边 = 显式链接（实线）+ 高相似度（虚线，阈值可调，需用户理解"这是算法猜测"——可解释原则）；
- 明确不做：社区发现、自动摘要聚类等在个人规模（<1 万条目）下收益不明的重能力。

## 2.9 复习/导出与会话资产

**现状**：无导出、无备份入口、会话重启即失（D-08）。

**目标设计**：

1. 【P1】**会话持久化与历史列表**：会话存后端（表结构见 03 文档），侧栏可切换/搜索历史会话；单条问答可删除。
2. 【P1】**导出**：条目/文档导出为 Markdown（含 frontmatter：标签、来源、创建时间）；整库导出为单一 `.zip`（SQLite 文件 + originals/ + 导出说明），兼作手动备份。
3. 【P2】**复习模式**：对"AI 生成草稿→已确认"的条目与高频引用条目，按最近最少复习排序提示回顾（简化版间隔重复，不做完整 SRS 算法——个人知识工具中 SRS 属锦上添花，避免过度设计）。
4. 【P1】**自动备份**：每日首次启动时复制 SQLite 到 `backups/`（保留最近 N 份），详见 [04 文档 §4.2](./04_数据安全与可靠性.md)。

## 2.10 Agent 辅助问答（边界内的智能化）

**现状**：RAG 问答主链路可用（检索→拼 context→LLM→引用展示），但无多轮上下文（D-09）；`src/agent/` 是与知识库无关的 SQL Agent 死桩（D-12）。

**目标设计**：

1. 【P1】**多轮对话**：`ask_question` 增加会话 id 与历史裁剪（最近 N 轮 + token 预算），检索用"当前问题 + 上一轮问题"合并查询以减少指代失败。
2. 【P1】**回答质量护栏**：零命中时不调 LLM 直接告知（现状已如此，C-03 保留）；低相关度命中（Top1 分数低于阈值）时在回答前显示"知识库中可能没有相关内容"警示条。
3. 【P2】**Agent 辅助整理**（只读 + 建议模式）：总结某文档、为条目建议标签、发现疑似重复条目、生成关联建议——**全部输出进"建议面板"，逐条采纳才写库**（[04 文档 §4.6](./04_数据安全与可靠性.md) 为硬约束）。
4. 【P0，工程卫生】**处置 `src/agent/` 死代码**：二选一——(a) 直接删除；(b) 若保留作统一模板占位，重写 types 为知识域概念并加 README 注明"未接线"。推荐 (a)：无引用的 SQL 桩代码只会误导后续维护者以为存在 Agent 能力。
