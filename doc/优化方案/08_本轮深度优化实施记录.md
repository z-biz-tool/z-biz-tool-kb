## 2. 调查记录

### 2.1 根因不是「忘了原子写」，是**同一套规则写了两遍**

2026-10-05 那轮修 D-07（明文 API key 以 0644 落盘）时，
`save_llm_config` 已经改成了一套相当讲究的写法：
同目录临时文件 → 显式 0600 → `write_all` → `sync_all` → `rename` → 再 `harden_file` 钉一次权限。

而**同一个文件**里的 `save_document` 还在用裸 `fs::write` 写文档元数据与文档切片。

`fs::write` = 「创建 + 截断 + 写」三步连做。写到一半崩掉、或磁盘写满，
盘上留下的是**半截 JSON** —— 下次读回来就是坏文件。
（仓里 2026-10-05 已经加了「一份文件坏掉不拖垮整体」的容错，
所以用户看到的是「这个文档不见了」，而不是明确报错 —— 那种静默更难查。）

⇒ 与家族里反复记的那条同源：**同一套规则在两侧各写一遍，必然漂移**。
这里漂移出来的差，是「一半的写盘是原子的、一半不是」。

### 2.2 能力边界要说清楚：两次 rename **不是一个**原子操作

`save_document` 要写**两个文件**（元数据 + 切片）。
两次 `rename` 各自原子，但**两次之间不是原子的**。
中途崩溃的最坏结果是「元数据是新的、切片是旧的」，
而**不是**「某个文件是半截的」—— 后者才是会毁掉数据的那种。
这一点写进了 `write_atomic` 的注释里，别把它说得比实际强。

## 3. 改动清单

### 3.1 `src-tauri/src/rag.rs`

新增**全仓唯一**的写盘实现：

```rust
fn write_atomic(path: &Path, contents: &str, what: &str, mode: u32) -> Result<(), String>
```

- 临时文件与目标**同目录**（跨文件系统的 `rename` 不是原子的）。
- 临时文件先设好权限（`mode`）再写，避免出现「先按 umask 建好、再 chmod」的窗口。
- `write_all` + `sync_all` 后才 `rename`。
- **每一条失败路径都清残留临时文件**（写失败、rename 失败各一处）——
  否则盘上会多一个半截产物，而按扩展名扫目录的加载逻辑可能把它当正常文件读。
- 非 unix 分支保留 `fs::write`（没有 0600 语义，rename 那套也不适用）。

两个调用点都改为走它：
- `save_document`：元数据 0644、切片 0644（**文档不是密钥，不该顺带收紧权限**）。
- `save_llm_config`：0600（沿用原口径）。

### 3.2 `src-tauri/tests/doc_store.rs`（8 → 14 条）

| 用例 | 钉住什么 |
|---|---|
| `保存文档后_没有残留临时文件` | 两个目录都不许留 `.tmp` |
| `反复保存同一文档_内容始终完整可解析` | 反复覆盖后读回来始终是**完整** JSON（反向对照：别为了原子把内容写坏） |
| `保存文档失败时_不会留下半截的目标文件` | 失败路径上目标文件不是半截的 |
| `rename_失败时_不留残留临时文件` | 造「临时文件写成功、rename 失败」（把目标路径占成目录）⇒ 清残留那条路被走到 |
| `文档文件权限不被意外收紧` | 元数据与**切片**都必须是 0644（只查一个等于没查） |
| `源码里_不再有裸的_fs_write` | **源码文本审计**：裸 `fs::write(` 只允许出现在 `write_atomic` 自己的非 unix 回退分支里 |

### 4.1 变异反向验证

| 变异 | 结果 |
|---|---|
| M1 `save_document` 回退成裸 `fs::write` | 失败 1 条 ✅（源码审计抓到） |
| M2 `rename` 失败时不清理残留 | 失败 1 条 ✅ |
| M3 文档切片权限收紧成 0600 | 失败 1 条 ✅ |
| M4 **写入阶段**失败时不清理残留 | **没咬住** ❌ —— 见下 |

> ⚠️ **M4 的诚实结论**：当 `File::create` 就失败时（目标目录不存在），
> **临时文件根本没被创建**，所以「不清理」在盘面上**看不出差别** ——
> 那是个**语义等价的变异**，不是判据漏了。
> 真正有差别的是「`create` 成功但 `write_all` 失败」（磁盘满），
> 那条路**没法用测试覆盖**（要造磁盘满或做故障注入）。
> 所以：**`rename` 失败那条清理由用例钉住；写入阶段失败那条只有代码审查保证，没有用例。**
> 这条如实记在这里，别让下一个人以为四条都有网。
